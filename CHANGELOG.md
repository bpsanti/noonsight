# Changelog

## Unreleased

- Routing, off by default: `routing.enabled`, `routing.targets` (`launcher`, `subagents`), `routing.respect_explicit`, `routing.yield_when_env`, `routing.table` and `routing.default`. A task's scope picks a row of options in order of preference, and the first whose model is declared under `models` wins, so an undeclared model such as Fable is never chosen. `sextant run` adds `--model` and `--effort` to the claude command line; the agent call hook sets the call's `model` and `effort`. The rules delivered are the routed model's. Routing yields to `--model` or a call's `model`, a definition's or a built-in subagent's own model, a fork, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`, `SEXTANT_ROUTING=off` and the variables of `yield_when_env`; an effort the caller set is kept. With routing off, no call changes beyond the rules. See `docs/configuration.md`.
- The decision log records `routing` and `routing_reason` on every `launch`, `agent-call` and `agent-result` line, with the chosen model and effort, the options passed over and the variable a route yielded to.
- `sextant run --task <text>`: without a scope, the scope comes from the task text, `--task` or the prompt right after `-p`, through the scopes' matchers, and is passed to the session as `SEXTANT_SCOPE`.
- The `claude` preset, version 1.1.0: a routing table for its five scopes (`investigate` to Fable at high effort, else Opus; `build` and `review` to Opus at high; `routine` to Sonnet at medium; `digest` to Sonnet for a session and Haiku for a subagent, at medium), each row with its basis and sources in `presets/claude/SOURCES.md`. The preset schema accepts a `routing.table` whose rows name models by alias.
- `sextant check` says whether routing is on, shows its table, and says when sessions started from its environment yield.
- Live tests for routing (`SEXTANT_LIVE_LOGIN=1 npm run test:live`): `route-subagents`, `explicit-model` and `orchestrator-env` for subagents, and a routed `sextant run` without `--model`.
- `sextant run [--scope <scope>] [--] <claude arguments>`: starts `claude` with the rules for its model in the system prompt, through `--append-system-prompt-file`. The model is taken as Claude Code takes it (`--model`, `ANTHROPIC_MODEL`, the `model` setting), the scope from `--scope` or `SEXTANT_SCOPE`. An `--append-system-prompt` someone else passes is kept, and an `--append-system-prompt-file` is merged into the launcher's file, since Claude Code keeps only the last one. Each launch logs an `event: "launch"` line. See `docs/launcher.md`.
- `SessionStart` recognizes the rules `sextant run` put in the system prompt: at `startup`, `clear` and `compact`, when the Claude Code process was started with the launcher's file and the file holds the rules the hook decided on, it delivers nothing and logs `delivered: "launcher"`. When the launcher's rules are for another model, it delivers the session's model's rules with a note that the others do not apply.
- Live tests for the launcher (`SEXTANT_LIVE_LOGIN=1 npm run test:live`): an explicit model with the hooks, `claude -p` without them, and another `--append-system-prompt` or `--append-system-prompt-file` on the same command line.
- The `claude` preset, version 1.0.0: 16 rules for `claude-fable-5-2`, `claude-opus-5-5`, `claude-sonnet-5-5` and `claude-haiku-5-5`, each adapted from Anthropic's prompting guide for that exact model, and five scopes, `investigate`, `build`, `review`, `routine` and `digest`, with descriptions and no matchers. Eight rules ship on and eight off. No rule is delivered in a place where Claude Code 2.1.325 already sends the same advice: `fable-5-2/finish-work` reaches subagents only, because Fable 5.2 sessions already get it. `presets/claude/SOURCES.md` gives the source, effect and cost of every rule.
- Preset format: every rule must state `effect` and `cost` besides its `source`, every preset scope a `description` and a `source`, and a preset can record under `claude_code` the Claude Code version its rules were compared with. A preset rule must fit the delivery limit on its own, and a model's preset rules together with every rule on, so turning on a rule never makes a configuration too long.
- `sextant init` writes the configuration file from the preset, declaring each of its models with `"use": "preset"`; it never replaces an existing file.
- `sextant models` lists each declared model with every rule it can receive, on or off, with source, effect and cost; the preset's models that are not declared; and the models the decision log has seen that are not declared. `--json` prints the same as JSON.
- Live tests for the preset (`SEXTANT_LIVE_LOGIN=1 npm run test:live`): `system-prompt` reads the system prompt Claude Code sends each of the four models, in a session and in a subagent, and fails when a preset rule is delivered where Claude Code already gives its advice, or when what Claude Code sends changes; `preset-hash` checks that the real preset reaches a session and a subagent and that the decision log records the hash `sextant resolve` gives.
- The installed preset's scopes are now declared for every configuration, since the package ships one.
- Task scopes: a scope can declare `match`, regular expressions run case-insensitively over a subagent's description and task text; the preset's scopes can declare them too, and a user scope of the same name replaces only the keys it gives. A session takes its scope from `SEXTANT_SCOPE`; a subagent from the scope whose matcher matches earliest in its task, and never from the session. An undeclared scope only means the rules for every scope. See `docs/configuration.md`.
- Place: `session.unattended_when_env` lists environment variables that put a session in the place `unattended`, so it receives the rules declared for sessions nobody is watching.
- The decision log records `scope`, `place`, `scope_source`, and when they apply `unknown_scope`, `scope_matcher`, `unattended_env` and `task_text_cut`.
- `sextant check` reports two scopes whose matchers match the same example text, and says which scope and place sessions started from its environment get. A matcher that is not a valid regular expression, that matches every plain task text, or that has a shape known to backtrack catastrophically (a leading `.*` with no `^`, nested unbounded quantifiers such as `(a+)+`, or overlapping unbounded quantifiers in a row such as `\w+\w+`) refuses the configuration, naming the scope and the pattern.
- Live tests for scopes (`SEXTANT_LIVE_LOGIN=1 npm run test:live`): two sessions and two subagents on the same model, in two scopes, return different verification words.
- `sextant watch enable` and `sextant watch disable`: an optional watcher, off by default, that installs the hooks into each new Claude Code configuration directory made in the home directory, as `sextant install --account <dir>` does. It runs as a launchd agent on macOS and a systemd user service on Linux, and watches only the entries directly in the home directory. `sextant check` says whether it is on and runs. The first session of a brand-new login can still start without the rules; see `docs/install.md`.
- Subagent hooks: `PreToolUse` on the agent tool (matcher `Agent|Task`) predicts the model each subagent will run on, in Claude Code's order (fork, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`, the call's `model`, the subagent's definition, the built-in subagents' own models, `CLAUDE_CODE_SUBAGENT_MODEL`, the parent's model), and adds that model's rules for the place `subagent` to the end of the subagent's task text. It never changes the model or the effort. `PostToolUse` compares the prediction with the model the subagent started on (`resolvedModel`), logs `match` or `MISMATCH`, and warns on a mismatch. An undeclared or unknown model only warns. See `docs/hooks.md`.
- Configuration: `subagents.delivery` (`prompt` or `off`), `subagents.permission` (`allow`, `ask` or `passthrough`: the permission decision returned with a changed call, since auto mode can deny a call a hook changed without one) and `subagents.on_mismatch` (`warn` or `ignore`).
- `sextant install` adds the two subagent hooks, and running it again upgrades an earlier install; `sextant check` reports an install that lacks them or whose matcher was changed.
- Live tests for subagents (`SEXTANT_LIVE_LOGIN=1 npm run test:live`) run real sessions from the login of whoever runs them, with sextant's hooks given through `--settings`, so nothing is installed into that account.
- `sextant install` with no option now installs into the user settings of every Claude Code configuration directory of the account (`~/.claude`, the one in `CLAUDE_CONFIG_DIR`, and every directory in the home directory that holds a Claude Code configuration), with no administrator rights. It reaches logins whose organization delivers server-managed settings, where Claude Code ignores the managed settings files. `uninstall` removes them all. The machine-wide install moved to `sextant install --managed`. See `docs/install.md`.
- `sextant check` lists every Claude Code configuration directory and says which install reaches it, including a login whose server-managed settings shadow the machine-wide install, or turn its hooks off.
- `SessionStart` without a model, as in every `claude -p` run, now takes it from the `--model` argument of the Claude Code process, `ANTHROPIC_MODEL`, or the `model` setting, in Claude Code's order, and logs which one in `model_source` and `model_from`. It warns only when none names a model, or when the one that does cannot be pinned down. See `docs/hooks.md`.
- Session hooks: `SessionStart` and `PostModelSwitch` give each Claude Code session the rules for the model it runs on, and after `/model` say that the earlier rules no longer apply. They always exit 0, never use the network, and never block; an undeclared model only warns, and a refused configuration delivers nothing. See `docs/hooks.md`.
- Decision log: one JSON line per decision in `~/.local/state/sextant/decisions.jsonl`.
- `sextant install` and `sextant uninstall`: for one Claude Code configuration directory with `--account <dir>`, or machine-wide with `--managed`, as sextant's own file in Claude Code's `managed-settings.d/` (administrator rights once). Installing twice changes nothing, and other hooks and settings are kept. See `docs/install.md`.
- `sextant check`: the configuration, every install, managed settings that stop hooks, the Claude Code version and the last decision.
- The rules for any model, scope and place must now fit in 9,500 characters, leaving room for the model-change note.
- Live tests (`npm run test:live`) drive real interactive Claude Code sessions; the tier that sends no prompt runs in CI against a pinned Claude Code version. See `docs/verification/claude-code.md`.
- TypeScript project with a test run on Node 20 and 22 in CI.
- Configuration schema (`schema/sextant.schema.json`) and preset schema (`schema/preset.schema.json`).
- `sextant resolve`: shows which rules a model receives for a task scope and a place, with the exact text that would be delivered.
- A configuration with any problem is refused whole, with its problems listed: schema problems first, then preset problems, then the rest.

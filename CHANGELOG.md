# Changelog

## Unreleased

- Task scopes: a scope can declare `match`, regular expressions run case-insensitively over a subagent's description and task text; the preset's scopes can declare them too, and a user scope of the same name replaces only the keys it gives. A session takes its scope from `SEXTANT_SCOPE`; a subagent from the scope whose matcher matches earliest in its task, and never from the session. An undeclared scope only means the rules for every scope. See `docs/configuration.md`.
- Place: `session.unattended_when_env` lists environment variables that put a session in the place `unattended`, so it receives the rules declared for sessions nobody is watching.
- The decision log records `scope` and `place`.
- `sextant check` reports two scopes whose matchers match the same example text, and says which scope and place sessions started from its environment get. A matcher that is not a valid regular expression, or that matches every plain task text, refuses the configuration.
- Live tests for scopes (`SEXTANT_LIVE_LOGIN=1 npm run test:live`): two sessions and two subagents on the same model, in two scopes, return different verification words.
- `sextant watch enable` and `sextant watch disable`: an optional watcher, off by default, that installs the hooks into each new Claude Code configuration directory made in the home directory, as `sextant install --account <dir>` does. It runs as a launchd agent on macOS and a systemd user service on Linux, and watches only the entries directly in the home directory. `sextant check` says whether it is on and runs. The first session of a brand-new login can still start without the rules; see `docs/install.md`.
- Subagent hooks: `PreToolUse` on the agent tool (matcher `Agent|Task`) predicts the model each subagent will run on, in Claude Code's order (fork, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`, the call's `model`, the subagent's definition, the built-in subagents' own models, `CLAUDE_CODE_SUBAGENT_MODEL`, the parent's model), and adds that model's rules for the place `subagent` to the end of the subagent's task text. It never changes the model or the effort. `PostToolUse` compares the prediction with the model the subagent started on (`resolvedModel`), logs `match` or `MISMATCH`, and warns on a mismatch. An undeclared or unknown model only warns. See `docs/hooks.md`.
- Configuration: `subagents.delivery` (`prompt` or `off`), `subagents.permission` (`allow`, `ask` or `passthrough`: the permission decision returned with a changed call, since auto mode can deny a call a hook changed without one) and `subagents.on_mismatch` (`warn` or `ignore`).
- `sextant install` adds the two subagent hooks, and running it again upgrades an earlier install; `sextant check` reports an install that lacks them or whose matcher was changed.
- Live tests for subagents (`SEXTANT_LIVE_LOGIN=1 npm run test:live`) run real sessions from the login of whoever runs them, with sextant's hooks given through `--settings`, so nothing is installed into that account.
- `sextant install` with no option now installs into the user settings of every Claude Code configuration directory of the account (`~/.claude`, the one in `CLAUDE_CONFIG_DIR`, and every directory in the home directory that holds a Claude Code configuration), with no administrator rights. It reaches logins whose organization delivers server-managed settings, where Claude Code ignores the managed settings files. `uninstall` removes them all. The machine-wide install moved to `sextant install --managed`. See `docs/install.md`.
- `sextant check` lists every Claude Code configuration directory and says which install reaches it, including a login whose server-managed settings shadow the machine-wide install, or turn its hooks off.
- `SessionStart` without a model, as in every `claude -p` run, now takes it from the `--model` argument of the Claude Code process, `ANTHROPIC_MODEL`, or the `model` setting, in Claude Code's order, and logs which one in `model_source` and `model_from`. It warns only when none names a model, or when the one that does cannot be pinned down. See `docs/hooks.md`.
- Session hooks: `SessionStart` and `PostModelSwitch` give each Claude Code session the rules for the model it runs on, and after `/model` say that the earlier rules no longer apply. They always exit 0, never use the network, and never block; an undeclared model only warns, and a refused configuration delivers nothing. See `docs/hooks.md`.
- Decision log: one JSON line per decision in `~/.local/state/sextant/decisions.jsonl`.
- `sextant install` and `sextant uninstall`: for one Claude Code configuration directory with `--account <dir>`, or machine-wide with `--managed`, as sextant's own file in Claude Code's `managed-settings.d/` (administrator rights once). Installing twice changes nothing, and other hooks and settings are kept. See `docs/install.md`.
- `sextant check`: the configuration, every install, managed settings that stop hooks, the Claude Code version and the last decision.
- The rules for any model, scope and place must now fit in 9,500 characters, leaving room for the model-change note.
- Live tests (`npm run test:live`) drive real interactive Claude Code sessions; the tier that sends no prompt runs in CI against a pinned Claude Code version. See `docs/verification/claude-code.md`.
- TypeScript project with a test run on Node 20 and 22 in CI.
- Configuration schema (`schema/sextant.schema.json`) and preset schema (`schema/preset.schema.json`).
- `sextant resolve`: shows which rules a model receives for a task scope and a place, with the exact text that would be delivered.
- A configuration with any problem is refused whole, with its problems listed: schema problems first, then preset problems, then the rest.

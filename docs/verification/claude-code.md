# Claude Code facts noonsight relies on

Each fact below names the Claude Code version and the date it was last checked, and how to check it again.
Recheck them all when raising the Claude Code version that CI pins (`.github/workflows/ci.yml`).

`npm run test:live` drives real interactive sessions through a terminal and sends no prompt and no request to Anthropic: a placeholder token gets Claude Code past sign-in, and `ANTHROPIC_BASE_URL` points at a closed local port.
`NOONSIGHT_LIVE_TOKENS=1` adds the checks that ask a model, which need a real token in `CLAUDE_CODE_OAUTH_TOKEN`.
`NOONSIGHT_LIVE_LOGIN=1` adds the subagent (one of them in auto mode), scope, preset, launcher and routing checks (`test/live/subagents.test.ts`, `test/live/scopes.test.ts`, `test/live/preset.test.ts`, `test/live/launcher.test.ts`, `test/live/routing.test.ts`), which send prompts from the Claude Code login of whoever runs them: they read no token, give noonsight's hook entries through `--settings`, and leave the person's own settings out with `--setting-sources project,local`, so nothing is installed into that account.
The preset checks send one short request to each of the four current models, Fable 5.2 included; in `claude -p`, Claude Code bills Fable usage to usage credits without asking, on plans where Fable draws on them.
Run them again whenever the preset changes or Claude Code is upgraded: the `system-prompt` check fails when what Claude Code sends each model changes.
`NOONSIGHT_LIVE_DELIVERY=1` adds the delivery probe of the benchmark pilot (`test/live/delivery.test.ts`): sessions against a local stand-in for the API that records every request and answers with fixed replies, so they run real turns, start subagents and compact without sending anything to Anthropic.
It also runs the corpus of the delivery benchmark (`test/live/delivery-corpus.test.ts`, [experiments/delivery](../../experiments/delivery/README.md)), whose sessions resume, switch models, compact and start subagents against the same kind of stand-in, and the subagent checks of `test/live/subagent-sources.test.ts`: `claude -p` sessions against the same kind of stand-in that start subagents defined in every place Claude Code reads, foreground subagents whose starts cannot be told apart, and a workflow's agents.
The lifecycle checks (`test/live/lifecycle.test.ts`) run with every `npm run test:live` against the same stand-in: they need `claude` and `expect` on PATH and are skipped without them.

The machine-wide install (`--managed`) is not checked live, because that would mean writing the real system directory of the machine running the tests.

To check it by hand on a disposable machine: run `sudo ... noonsight install --managed`, start `claude`, and confirm that `/status` lists the managed settings files and that `~/.local/state/noonsight/decisions.jsonl` gains a line.

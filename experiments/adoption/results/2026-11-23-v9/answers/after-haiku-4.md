Verdict: **Adopt with conditions.** Pilot it on a few people first, and keep it off for workflows and agent teams until you have checked those yourselves.

Reasons:
- **It targets the problem you describe.** It delivers each model's rules to every session and subagent that runs on that model, and re-delivers them when the model changes or the conversation is compacted, cleared, resumed or forked. That matches a team that mixes Opus, Sonnet, Haiku and Fable and starts many subagents.
- **The coverage numbers are strong and specific.** In the 2026-11-23 run on Claude Code 2.1.330, 3,090 of 3,090 requests with rules due held their model's rules (docs/evidence.md, D19), and 763 of 763 subagent requests did (D20). A user `CLAUDE.md` reached 88.2% of requests, and a `.claude/rules` folder reached 76.3% (D25, D26). Subagent coverage with a `CLAUDE.md` was 46.9% (D28). A skill per model reached 0% (D27).
- **It addresses a gap that native mechanisms leave open.** A `CLAUDE.md` never reaches the built-in Explore and Plan subagents, as Anthropic documents (README, "What it does not" section). Your many subagent sessions are where that gap matters most.
- **Its footprint is small and its failure mode is visible.** It has no runtime dependencies, its hooks never block anything, and `noonsight report` shows what was delivered. Hook cost is 80–150 ms per run (D33).
- **The benefit is narrower than the marketing.** Measured effects are real but limited: `verify-changes` raised test-after-edit rates on small Sonnet and Haiku tasks (R3, R14), and `carry-through` helped on a bug task for Sonnet (R15, R16). Across the paid pilot, no quality difference was found (B1: 133, 132 and 133 of 144 runs passed without rules, under noonsight, and with a `CLAUDE.md`). Quality was flat even as cost rose, and the tasks are small.

Conditions and risks:
- **Cost.** Measured per-run cost roughly doubled for `verify-changes` on the Sonnet fix task ($0.0240 to $0.0505, R6) and rose on the bug task ($0.0321 to $0.0494, R17). Haiku's fix-task cost also doubled, though from a low base ($0.0015 to $0.0033, R7). Set a budget check against your own usage before rolling it out widely.
- **Ship only the rules you have measured.** The preset includes rules with no measured effect (Opus 5.5 and Sonnet 5.5 rules listed as "No effect shown," and Fable's `code-ownership`, which Anthropic's guide says raises output tokens 70–80%). Turn on only the rules you test on your own tasks, and treat the preset's "on" defaults as a starting point to review, not a recommendation.
- **Turn off or avoid routing.** `routing` is off by default, and it changes model and effort for subagents. Its effects are not measured in the evidence (README limits), so it is a separate decision that should not come with the initial rollout.
- **Know the blind spots.** Workflow agents receive nothing. Subagents from plugins that noonsight does not read are predicted on the parent's model. Foreground subagent calls of one type that need different rules give their subagents nothing until their first Edit, Write or agent call. Agent-team teammates in split panes were not checked. Your team should know which of your sessions use these paths.
- **Version drift.** Every result is tied to a Claude Code version (2.1.326 to 2.1.330). Check which version your team runs. Anything that changes hook behavior in a newer release is unverified until you rerun the tests.
- **Machine-wide install.** `noonsight install` writes hooks into every Claude Code login on the machine, and it is per login. Each teammate installs it themselves. Repository-level rules in `.noonsight/noonsight.json` only take effect after each person runs `noonsight trust`, so check committed rule files in review as you would code.
- **Network use.** The classifier is off by default. If you turn it on, it sends the first 4,000 characters of a task to a small model through your own login.
- **Not verified here.** I read the repository's docs and evidence files but did not run `npm test` or the live tests, and I did not verify the numbers against the raw result files. Running `npm test` on your Claude Code version before the pilot would settle that.

What it guarantees: Through Claude Code's hooks, noonsight delivers the rules declared for each model into the requests of each session and subagent running on that model, and again when the model changes or the conversation is compacted, cleared, resumed or forked. The guarantee rests on one measured run (100% coverage of 3,090 requests on Claude Code 2.1.330, against a local stand-in for the Messages API), and it does not cover delivery to workflow agents or unread plugin subagents, and it does not guarantee the model follows the rules.

**Verdict: adopt with conditions.** Pilot it first, with the conditions below. Don't roll it out team-wide yet.

**Reasons**
- **It solves a real problem for a mixed-model team.** A shared `CLAUDE.md` gives every model every model's rules. In the benchmark pilot, only 18–29% of the rule text a model received was written for it. Subagents also don't see the session's conversation. noonsight sends each rule set only to the model it was written for, and it does this at startup, after `/model`, `/clear`, compaction and resume, and for subagents (README, `docs/hooks.md`).
- **Delivery is measured against real Claude Code, not just claimed.** The delivery fuzz run (2.1.328, 300 sessions) shows the `CLAUDE.md` alternative reaching only 87.4% of requests, `.claude/rules` 70.9% and skills 0%. For subagents, `CLAUDE.md` and `.claude/rules` reached 32.2%. Under noonsight, the first 60 sessions covered 650 of 650 requests and 121 of 121 subagent requests. Across all 300 sessions, coverage was 99.5%, and three sessions still broke the invariant.
- **Its failures are disclosed.** There are two known open bugs, F3 and F4. F3 is a resume's delivery lost to a second resume. F4 is a wrong-model resume after switching Sonnet→Haiku, which leaves the wrong rules in place for the rest of the session. Both are recorded in the corpus and neither is fixed.
- **Low operational risk.**
  - Hooks run in a median of about 80 ms of processor time, always exit 0, never block or deny a call, and use no network or credentials.
  - Setup is one reversible command, `NOONSIGHT_DISABLE=1` turns it off per session, and there are no runtime dependencies.
  - Routing and the classifier are off by default.
  - The MIT licence and the declared limitations are reasonable.
- **The rule effects are modest and uneven.** The documented effects are real but small. Sonnet and Haiku ran the tests after a one-file fix in 30/30 and 27/30 runs with the verify rule, against 0/30 without it, at about 46% more cost per run in the earliest run. Fable's report rule cut sentence length and semicolons. Several rules showed nothing: the carry-through rules on short tasks, and Haiku's carry-through on the 13-ticket backlog. Where the models already did the thing, the rules changed nothing.
- **No evidence it improves task success.** In the 588-run pilot, the verifier saw no measurable difference between conditions, and cost was 7% higher with noonsight. The authors explicitly make no quality claim.

**Conditions and risks**
- **Version pinning.** It is "early development" (v0.1.0), "nothing is published yet", and you'd install from a clone. It depends on undocumented-ish Claude Code behaviour, such as `PostModelSwitch`, `SubagentStart` and process-argument reading. Every verified fact is tied to a specific Claude Code version (2.1.325–2.1.329). Pin or test Claude Code upgrades, and rerun `npm run test:live` and the delivery benchmark before each upgrade.
- **Your subagent setup must be inside what it can predict.** It predicts a subagent's model before the start and warns on a mismatch, but it can't see plugin subagent definitions, `--agents`, managed definitions, mods, or agent-team teammates. Those get wrong rules or none. Check how much of your subagent use falls there.
- **Resumes and model switches are the weak spot.** A switch's or resume's delivery can be lost if the session ends before the next request, and F4 can leave the wrong model's rules in place. If your people switch models often with `/model` and `--continue`, expect occasional wrong or missing rules. Watch `noonsight report` for `MISMATCH` and `switched-again`.
- **Rules need ownership.** The benefit depends on rules you write or adopt. The preset's effects were small, and several of its rules have a cost. A rule on Sonnet or Haiku that makes it run tests adds cost. Review what is enabled (8 rules are on by default), and rely on `noonsight check` and the preset-update warnings when the preset changes.
- **Auto mode interaction.** If you turn routing on, a routed subagent call makes Claude Code's auto-mode classifier skip review of the other calls in that response, so they are refused and retried. Keep routing off unless you need it.
- **Shared configuration risk.** Project `.noonsight/noonsight.json` files add rules only after each person runs `noonsight trust`, which is a prompt-injection surface worth a policy. The optional classifier sends the first 4,000 characters of task text to a model, and its agreement was about 96–98% on 45 hand-labelled tasks, so it is not a guarantee.
- **Evidence limits.** The effect studies are small, the judge in the benchmark is Claude grading Claude, and the pilot ran on one laptop. I read the docs and result summaries, not the code, and I didn't run the tests. The results are the authors' own.
- **Suggested pilot.** Run it on a few people across all four models for 2–4 weeks, using the decision log to confirm rules reach the right models, and check that cost and quality don't degrade.

**What it guarantees:** It guarantees nothing absolute. It aims to put each model's own rules in front of that model, for sessions and subagents, through official Claude Code hooks, and it never blocks work. The strongest evidence is a fuzz test on one Claude Code version (99.5% coverage, with known failures after resumes and model switches), not a proof.

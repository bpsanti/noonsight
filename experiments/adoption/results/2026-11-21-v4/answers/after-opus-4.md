**Verdict: adopt with conditions.** Run a pilot first on a few people's machines, pinned to a known Claude Code version, before rolling it out to the whole team.

**Reasons**

1. **It solves a problem you actually have.** You run four models and many subagents. A `CLAUDE.md` can't pick rules by model, so every model reads every other model's rules. In the tool's benchmark, only 31.5% of the rule text in a `CLAUDE.md` request was meant for that request's model. A `CLAUDE.md` also never reaches the built-in Explore and Plan subagents, so subagent coverage was 32.2% (39 of 121). noonsight covered 100% of subagent requests, with 79% of the rule text meant for the request's model (`README.md:27-37`, `docs/evidence.md` D10 and D12).
2. **The delivery evidence is unusually careful.** It drove 300 random real Claude Code sessions through `/model`, `/compact`, `/clear`, resumes and subagents against a local stand-in for the API. 99.9% of requests (3,219 of 3,221) got their rules. The one failing session is a documented limit. The fuzzer found four bugs (F1 to F4), all fixed, with reproductions kept as tests. Every number in the docs is recomputed from committed raw files by `npm test` (`experiments/delivery/results/.../2026-11-21-d5fd71f/README.md`).
3. **It's low-risk to try.** The hooks never block anything and don't use the network (the optional classifier is the only exception). Each hook run takes 50–90 ms of processor time. There are no runtime dependencies. `noonsight uninstall` removes the hooks, and `NOONSIGHT_DISABLE=1` turns it off for one session.
4. **It's honest about its limits.** The README says that delivering a rule doesn't mean the model obeys it, and lists what it didn't measure.

**Conditions and risks**

- **Out of the box, your Opus and Fable sessions get nothing.** Every preset rule for Opus 5.5 and Fable 5.2 that is on by default applies only to unattended runs or subagents. A watched Opus or Fable session gets no rules, and Sonnet and Haiku get most of theirs only when a session has a scope. To get value, you'd need to set `session.unattended_when_env`, give sessions scopes (`NOONSIGHT_SCOPE`), and write your own rules (`README.md:44-48`).
- **The evidence is tied to one Claude Code version.** It was measured on 2.1.328/2.1.329, and all of it is from the last week (Nov 14–21). It also relies on behaviour Claude Code doesn't document. For example, the tool reads the undocumented `CLAUDE_CODE_SESSION_ATTENDED` variable to tell headless runs from watched ones. If a future version drops it, every session is silently treated as watched (`docs/verification/claude-code.md:34`). So pin your Claude Code version, and re-run `npm run delivery -- corpus` before each upgrade.
- **Parallel subagents can go without rules.** When one response starts several subagents of the same type that would need different rules (for example, different models), they may get none. The benchmark counts this case apart from its main numbers (`docs/hooks.md:247-259`). Your heavy subagent use is the setting where this is most likely to happen.
- **Several things were not measured:** `/resume` typed inside a session, forks, plan mode, agent teams, the `noonsight run` launcher, routing, the classifier, repository configurations, and subagents that make more than one request or edit files. The benchmark's stub never behaves like a real long-running agent.
- **It's still early.** Version 0.1 isn't on npm yet; you install from a git clone. The default install also writes hooks into every Claude Code login on the account. Check that your organization's managed settings allow user hooks; `noonsight check` will tell you.
- **The rules' effect is a separate question.** The rule-effect results come from small tasks with 30–40 runs per variant. Some rules helped, such as `verify-changes` and Sonnet's `carry-through`. Others changed nothing, and some about doubled the cost of a cheap task. Measure your own rules before trusting them.
- **If you turn on routing in auto mode**, any subagent call routing changes makes Claude Code refuse the other calls in the same response until Claude makes them again. Routing is off by default; leave it off.

**What it guarantees:** On Claude Code 2.1.328, each request carries the rules its own resolver picks for that request's model, scope and place, and no unretired rules of other models, in 99.9% of benchmarked requests. That rests on Claude Code's hook behaviour staying as checked on that version, and on noonsight's resolver being right, since the benchmark grades delivery against that same resolver. It does not guarantee the model follows the rules.
